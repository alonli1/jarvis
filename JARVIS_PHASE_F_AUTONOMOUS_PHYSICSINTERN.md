## Important change to the Phase F bootstrap

Do not block on the user-only Codex plugin skill `$physics-intern:init-physics-intern`.

PhysicsIntern officially supports an upstream script bootstrap for Codex:

```bash
./init-physics-intern.sh --host=codex <workspace>
```

For autonomous Phase F, use that official upstream script bootstrap instead of the explicit-user-only plugin trigger.

Create a separate empty workspace outside the Jarvis repository when possible.

Preferred locations:
1. an existing project-designated scratch/evaluation directory;

4. `/tmp/jarvis-physicsintern-phase-f`.

Do not initialize PhysicsIntern directly inside the Jarvis repository.

If the sandbox blocks one location, try another writable scratch/temp location before surfacing a blocker.

./init-physics-intern.sh --host=codex <workspace>

## 4. Mechanically isolate Honey

All PhysicsIntern scientific validation runs must execute with Codex plugins disabled.

Use the installed Codex build's all-plugins-off mechanism, preferably:

```bash
codex --disable plugins
```

or the corresponding:

```bash
codex exec ... --disable plugins
```

form when noninteractive execution is appropriate.

This is intentionally broader than disabling only Honey.

The PhysicsIntern methodology is already local to the generated workspace under `.agents/skills/` and `.codex/agents/`, so the bootstrap plugin is not needed during the research runs.

Do not uninstall Honey.
Do not delete Honey's installation/cache.
Do not modify the user's global plugin configuration.

If the generated project-local config supports disabling the plugin feature, set that too as defense in depth, but do not rely on it alone. Prefer the process-level `--disable plugins` switch for the actual scientific runs.
